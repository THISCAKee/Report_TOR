# ระบบตารางภาระงานรายวัน — Design Spec

## เป้าหมาย

สร้างเว็บแอป Next.js สำหรับบันทึกภาระงานรายวันตามรายการจากเอกสาร TOR ของบุคลากร โดยผู้ใช้เลือกวันที่ เลือกรายการภาระงาน เขียนรายละเอียด และแนบไฟล์ได้หลายไฟล์ ข้อมูลเก็บใน browser ด้วย `localStorage` จึงใช้งานได้โดยไม่ต้องมี backend หรือระบบล็อกอินในระยะแรก

## ข้อมูลอ้างอิงจาก TOR

ระบบจะเตรียมรายการภาระงานเป็น 4 หมวด:

- งานหลัก: 1.1–1.8
- งานรอง: 2.1–2.3
- งานทำนุบำรุงศิลปะและวัฒนธรรม: 3.1
- งานอื่น ๆ: 4.1–4.2

รายการแต่ละรายการมีชื่อที่แสดงในภาษาไทย รหัสหมวด น้ำหนัก และเกณฑ์ระดับเป้าหมาย 1–5 เพื่อให้ระบบแสดงบริบทของงานระหว่างบันทึก โดยรอบแรกจะใช้รายการจากเอกสารเป็นข้อมูลตั้งต้นแบบคงที่

## แนวทาง UX/UI

ใช้แนวคิด “สมุดบันทึกภาระงานดิจิทัล” ที่เน้นการกรอกเร็วและตรวจสอบย้อนหลังง่าย:

- พื้นหลังอุ่นอ่อน `#F5F3EE` ให้ความรู้สึกเป็นเอกสารงานราชการร่วมสมัย
- สีหลักหมึกกรมท่า `#17233F`, น้ำเงินใช้งาน `#2F56D3`, สีทองเน้น `#D7A83E`, สีเขียวสถานะ `#2E8B72`
- ใช้ Anuphan เป็นฟอนต์หลักทุกขนาด น้ำหนัก 400/500/600/700 ตามลำดับชั้น
- เดสก์ท็อปเป็นเลย์เอาต์สองคอลัมน์: ฟอร์มบันทึกทางซ้าย และรายการงานของวันที่เลือกทางขวา
- หน้าจอมือถือเรียงเป็นคอลัมน์เดียว โดยฟอร์มอยู่ก่อนรายการ
- องค์ประกอบสำคัญมี focus ring ที่เห็นได้ชัด, hover state ที่สุภาพ และเคารพ `prefers-reduced-motion`

### โครงหน้าหลัก

1. Header: ชื่อระบบและคำอธิบายสั้น พร้อมตัวบอกว่าเก็บข้อมูลในเครื่อง
2. Summary strip: วันที่ที่เลือก, จำนวนรายการวันนี้, จำนวนไฟล์แนบ
3. Work entry panel:
   - date input แบบ native พร้อม locale ไทยในข้อความประกอบ
   - select รายการภาระงานแบบ optgroup ตาม 4 หมวด
   - แสดงน้ำหนักรายการที่เลือก
   - textarea รายละเอียดการทำงาน
   - multiple file input และรายการไฟล์รอแนบ ชื่อ/ขนาด/ปุ่มลบ
   - ปุ่ม “บันทึกภาระงาน” และสถานะ validation
4. Daily log panel:
   - รายการที่บันทึกของวันที่เลือก
   - badge หมวดและน้ำหนัก
   - รายละเอียดและไฟล์แนบ
   - ปุ่มแก้ไข/ลบ
   - empty state ชวนให้เริ่มบันทึก

## สถาปัตยกรรมและ data flow

- เป็น Next.js App Router แบบ client component สำหรับหน้าหลัก เพราะต้องใช้ file input และ `localStorage`
- `lib/workload-data.ts` ถือข้อมูลรายการ TOR แบบ readonly และ type `WorkloadDefinition`
- `lib/storage.ts` ห่อการอ่าน/เขียน `localStorage` ด้วย key เดียวและ guard กรณีข้อมูลเสียหรือไม่มี browser storage
- `lib/types.ts` ถือ type `WorkLog`, `Attachment`, และข้อมูลฟอร์ม
- `app/page.tsx` คุม state วันที่เลือก รายการ log และโหมดแก้ไข
- `components/EntryForm.tsx` รับรายการ TOR และ callback สำหรับ save
- `components/DailyLog.tsx` แสดงรายการของวันที่เลือกและส่ง callback edit/delete
- `components/SummaryStrip.tsx` แสดงตัวเลขสรุปแบบ derived state
- ไฟล์แนบในระยะนี้เก็บเป็น metadata และ `data URL` ใน localStorage เพื่อให้เปิดดู/ดาวน์โหลดได้หลัง refresh โดยจำกัดขนาดรวมต่อรายการที่ 10 MB และแสดง error ชัดเจนเมื่อเกิน

ข้อมูลที่บันทึก:

```ts
type WorkLog = {
  id: string;
  date: string; // YYYY-MM-DD
  workloadId: string;
  detail: string;
  attachments: Attachment[];
  createdAt: string;
  updatedAt: string;
};

type Attachment = {
  id: string;
  name: string;
  size: number;
  type: string;
  dataUrl: string;
};
```

การบันทึกใหม่จะเพิ่มรายการพร้อม `createdAt`; การแก้ไขจะคง `id` และอัปเดต `updatedAt`; การลบจะต้องยืนยันผ่าน dialog แบบ native ที่อ่านได้ด้วยคีย์บอร์ด

## Validation และ error handling

- วันที่ต้องมีค่า
- รายการภาระงานต้องถูกเลือก
- รายละเอียดต้องมีข้อความที่ไม่ใช่ whitespace
- เลือกไฟล์ได้หลายไฟล์ทุกนามสกุล แต่ไฟล์รวมต่อรายการต้องไม่เกิน 10 MB
- หากอ่านไฟล์ไม่ได้หรือพื้นที่ `localStorage` ไม่พอ ให้ไม่บันทึกข้อมูลบางส่วน และแสดงข้อความแก้ปัญหาในฟอร์ม
- การเปิดหน้าจะอ่านข้อมูลที่เก็บไว้; JSON ที่ parse ไม่ได้จะถูกละทิ้งอย่างปลอดภัยและเริ่มด้วยรายการว่าง
- การแก้ไขต้องโหลดข้อมูลเดิมกลับเข้าฟอร์ม และผู้ใช้เลือกเพิ่ม/ลบไฟล์แนบได้

## ขอบเขตที่ไม่รวมในรอบนี้

- ระบบผู้ใช้/สิทธิ์/ล็อกอิน
- ฐานข้อมูลหรือการ sync ข้ามเครื่อง
- การแก้ไขรายการ TOR ผ่านหน้าเว็บ
- รายงานส่งออก PDF/Excel และการอนุมัติโดยผู้บังคับบัญชา

## เกณฑ์ยอมรับ

- สามารถเลือกวันที่และเห็นเฉพาะงานของวันที่นั้น
- เลือกรายการจาก TOR ได้ครบทั้ง 4 หมวด พร้อมน้ำหนัก
- บันทึกรายละเอียดและไฟล์หลายไฟล์ทุกนามสกุลได้ภายในข้อจำกัด 10 MB
- รีเฟรชหน้าแล้วข้อมูลเดิมยังอยู่ใน browser
- แก้ไขและลบรายการได้
- หน้าจอใช้งานได้ทั้ง desktop และ mobile และมี keyboard focus ที่มองเห็นได้
- `npm run lint` และ build ของ Next.js ผ่าน
